What is included: editable MIT-licensed Next.js frontend source. No backend, WordPress theme, CMS, payment integration, booking engine, or account security is included. Author-generated demo imagery is included under MIT. You will need basic React/TypeScript knowledge for code changes.

1. Install and run

  1. Clone the repository or extract its source download, then open the project folder in your editor.
  2. Install Node.js 22.19 or newer. Install pnpm by running npm install -g pnpm@12.6.0 in a terminal. Confirm with node --version and pnpm --version.
  3. Open a terminal inside the talkwer folder. Install the exact locked dependencies:
pnpm install --frozen-lockfile
pnpm dev

Open http://localhost:3560. Stop the server with Ctrl+C. Internet access is needed for the first dependency install, but the bundled font and local images need no external font or photo service.

For a production preview, stop the dev server and run:

pnpm build
pnpm start

Open http://localhost:3000. Use this production preview for visual review if development CSS is missing. Run pnpm verify to check lint, TypeScript, filenames, image sizing/bytes, and production build.

3. Customize your site

Brand, domain, and social previews

Copy .env.example to .env.local and set NEXT_PUBLIC_SITE_URL=https://your-domain.com. This is a public value, not a secret. Rebuild after changing it. Edit the site name, title, description, social handle, and default social image in src/lib/seo.ts. Replace the sample wordmark in the navbar, footer, and auth/dashboard shells; search the source for talkwer to find brand references.

Photography

The repository includes author-generated demo photos under the MIT license. Replace files in public/ using the same filenames to keep existing references working. Alternatively update image paths in feature content. Use commercially licensed images and descriptive alt text. For next/image with fill, keep the sizes attribute. Avoid oversized photos; pnpm check:public-image-bytes checks the 400 KB source-image budget. To use your own brand icon, replace src/app/icon.svg, src/app/favicon.ico, and src/app/apple-icon.png.

Destinations, tours, and stories

Edit destinations in src/features/home/content/destinations.ts and tours in src/features/home/content/tours.ts. Copy an existing record and keep its required fields; shared type definitions are in src/shared/types/domain.ts. Tour itineraries and imagery are nested inside the tour record. Stories live in src/features/stories/content/stories.ts. Check the slug helpers under each feature's lib/ folder before changing identifiers; links, detail routes, and generated sitemap entries depend on them. Run pnpm verify after changes.

Color, spacing, and motion

Edit tokens and global utilities in src/app/globals.css. Tailwind CSS v4 is configured through this stylesheet and postcss.config.mjs; there is no tailwind.config.ts. The visual system is dark with orange accents. Some page sections use explicit color classes, so changing one token does not recolor every section. Shared pad-x spacing and feature section classes control layout. GSAP helpers are in src/lib/useGsap.ts; retain context cleanup and reduced-motion handling when editing animations.

Copy and languages

Edit interface messages in dictionary/en.json, es.json, and ja.json. Keep the same message keys and ICU variables in each language. Edit remaining editorial text in feature content/ modules. Locale routing is in src/i18n/routing.ts, regional formatting in src/i18n/regional.ts. Adding a language also requires request loading, dictionaries, sitemap alternates, and SEO mapping updates.

Adding a page

The default homepage uses the static Pages Router entry src/pages/[locale]/index.tsx and build-time copy in src/features/home/lib/get-static-home-props.ts. Other pages use the App Router. Navigation across routers loads a new document. Fonts are defined in src/app/globals.css.

Use src/features/about as an example: a feature entry composes files in sections/, with copy in content/. Add a thin route under src/app/[locale]/your-page/page.tsx that imports the feature. Include metadata and locale handling from a sibling route, then update navigation and the sitemap. Do not put a whole page's UI inside the route file.

4. Demo behavior and integration boundaries

  • Login/register: preview forms navigate without validating credentials or creating accounts. Dashboard URLs are public. Replace with real authentication, server-side session checks, and authorization before storing private data.
  • Booking: sample times and traveler data are passed using browser session storage. No availability is checked and no slot is reserved. Use sample contact details; closing the browser session clears the handoff.
  • Checkout: sample card fields are read-only and populated by the demo autofill control. No card details are sent or saved. A local confirmation is created; no payment, booking, email, or calendar invite occurs. Integrate a provider's hosted/tokenized checkout and validate prices and inventory on a server for real sales.
  • Dashboards: sample records and local UI state demonstrate layouts. Edits do not update a database or publish the website.
  • Contact: opens the visitor's email app using mailto:. It cannot guarantee delivery. Replace sample addresses in contact content with your own; an API/email service must be implemented separately for direct submissions.
  • Newsletter: validates the input and reports demo feedback. It does not subscribe, store, or send the address. Connect your email service separately.
  • Storage notice: an optional reusable component is provided, but the default demo does not display a consent overlay because no analytics or advertising services are installed. Review any scripts you add separately.
  • Sample copy: reviews, ratings, business history, pricing, partner names, and policy text are illustrative. Replace these with your own accurate content and policies.

5. Deployment and troubleshooting

Deploy the source to a host that supports Next.js 16 and Node.js 22.19+. Configure the public site URL, install dependencies, run pnpm build, and serve with pnpm start, or use a host's supported Next.js integration. The app contains middleware/proxy routing and image optimization; this package is not an out/ folder for drag-and-drop static hosting. No database or secret environment variables are needed for the demo.

  • Port in use: stop the other server or run pnpm exec next start -p 3001.
  • Missing CSS in dev: stop the dev server and use the production build commands above.
  • Checkout redirects: enter from a tour's booking flow; the page needs the session handoff. Check that browser session storage is available.
  • Broken image: confirm spelling, file extension, and exact case. Hosting is often case sensitive even if your Windows machine is not.
  • Missing translation: compare keys in all three dictionaries and retain required ICU placeholders.
  • Wrong canonical domain: set NEXT_PUBLIC_SITE_URL and rebuild.
  • Build failure: use the documented Node/pnpm versions and install with the included lockfile. Share the full error and reproduction steps with support.
